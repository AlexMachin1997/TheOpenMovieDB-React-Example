# Form field

Binds `@repo/ui-core`'s [`Field`](?path=/docs/ui-core-field--docs) to a field of the surrounding
[`Form`](?path=/docs/ui-forms-form--docs) by name, and hands you the bindings to put on any control.

> **Reach for a bound field component first.**
> [`TextField`](?path=/docs/ui-forms-fields-text-field--docs),
> [`SelectField`](?path=/docs/ui-forms-fields-select-field--docs) and the rest are built on this and
> need no render prop. `FormField` is what you use when the control you want has no bound wrapper —
> including one that does not exist yet. `CheckboxGroup`, `Slider` and the date pickers are the
> deliberate gaps.

## Installation

```tsx
import { FormField, useForm } from '@repo/ui-forms';
```

## Usage

<Canvas sourceState='none' of={FormFieldStories.Default} />

```tsx
<FormField name='email' label='Email address' required>
	{(control) => <Input {...control} type='email' />}
</FormField>
```

You name the field; its value and validation state are already resolved. The reactivity comes from
TanStack's own `form.Field`, which `FormField` renders internally — nothing here adds to it.

There is **no `form` prop**: it comes from the surrounding `Form`, and rendering this without one
throws. The control's `id` defaults to the field's `name`, so `#email` finds it in the DOM.

## The `control` bag

Children receive `(control, field)`. `control` extends `Field`'s accessibility bindings with the
data wiring:

| Key                                                                    | From     |
| ---------------------------------------------------------------------- | -------- |
| `id`, `aria-describedby`, `aria-invalid`, `required` / `aria-required` | `Field`  |
| `name`, `value`, `onChange`, `onBlur`                                  | the form |

`control.value` is typed `unknown` by default, because the form travels by context and React context
cannot carry the form's data type. Declare it when you read it:

```tsx
<FormField<string> name='email' label='Email address'>
	{(control) => <Input {...control} value={control.value} />}
</FormField>
```

`onChange` is normalised: it accepts either a DOM change event or a raw value, so the same handler
serves an `Input` (`event.target.value`) and a `Checkbox` (a boolean). The second argument is the
full TanStack field API, for anything the bag doesn't cover.

### Controls with their own `value`

Some controls have a `value` prop meaning something else — Radix's `Checkbox` and `Switch` both take
a string `value` for form submission. Spreading the bag onto them is a **type error**, not a silent
bug, and the fix is to destructure:

```tsx
<FormField<boolean> name='terms' label='Accept the terms'>
	{({ value, onChange, ...control }) => (
		<Checkbox {...control} checked={value} onCheckedChange={onChange} />
	)}
</FormField>
```

Absorbing that is precisely what `CheckboxField` exists for.

## What it deliberately does not do

`FormField` never maps a control _name_ to a component — there is no `<FormField control='input' />`.
That would mean holding a registry of every control and how each reports a change, and every control
added later would need an entry in it. Connecting the control stays a one-line job, which is what
keeps this working with controls the library has never heard of.

The bound field components are the ergonomic answer instead: ordinary compositions, each knowing one
control, all built on this — [text](?path=/docs/ui-forms-fields-text-field--docs),
[textarea](?path=/docs/ui-forms-fields-textarea-field--docs),
[checkbox](?path=/docs/ui-forms-fields-checkbox-field--docs),
[switch](?path=/docs/ui-forms-fields-switch-field--docs),
[select](?path=/docs/ui-forms-fields-select-field--docs) and
[radio group](?path=/docs/ui-forms-fields-radio-group-field--docs).

## Validation timing

<Canvas sourceState='none' of={FormFieldStories.SubmitSurfacesErrorsOnUnvisitedFields} />

`showErrorsWhen` decides when a message becomes visible. `'touched'` (the default) covers the case
that matters most: submitting marks every mounted field touched, so an error appears even on a field
the user never visited.

> **`noValidate` used to be your problem, and no longer is.** `required` renders a _native_ `required`
> attribute, and the browser's own constraint validation blocks the `submit` event outright when it
> fails — the handler never runs, nothing validates, no message appears.
> [`Form`](?path=/docs/ui-forms-form--docs) sets `noValidate` and there is no prop that turns it off.

## `toFieldProps` — the translation underneath

Exported separately for driving `form.Field` or `useField` yourself:

```tsx
import { toFieldProps } from '@repo/ui-forms';

<form.Field name='email'>
	{(field) => (
		<Field label='Email address' {...toFieldProps(field)}>
			{(control) => <Input {...control} value={field.state.value} />}
		</Field>
	)}
</form.Field>;
```

It takes a TanStack field's state and returns the props `Field` accepts — nothing else. It contains
no reference to any `ui-core` component.

**One plain function covers both of TanStack's APIs**, because `form.Field`'s render prop and
`useField()` hand back the same `FieldApi` object. It is deliberately **not** a hook: `useField`
already calls `useStore(fieldApi.store)` with no selector, so the consuming component re-renders on
any state change already, and a hook here would subscribe a second time for nothing.

### Error normalisation

`meta.errors` holds whatever the validators produced — a `string` from a plain function, a
`{ message }` issue object from a Standard Schema validator like zod. `toFieldProps` reads both, and
returns `undefined` for anything it cannot render as text rather than leaving the field permanently
invalid-but-silent.

Only the first renderable message is returned, never a joined list.
