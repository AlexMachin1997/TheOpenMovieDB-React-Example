# Textarea field

A multi-line text input bound to a form field by name.

The same as [`TextField`](?path=/docs/ui-forms-fields-text-field--docs) apart from the control it
renders and the `rows` prop. Reach for it when the answer runs to more than one line.

<Canvas of={Stories.Default} />

## What it composes

| Part                                 | Component                                            | What it gives you                                          |
| ------------------------------------ | ---------------------------------------------------- | ---------------------------------------------------------- |
| The control                          | [`Textarea`](?path=/docs/ui-core-textarea--docs)     | The `<textarea>`, its states and styling                   |
| Label, description, error and layout | [`Field`](?path=/docs/ui-core-field--docs)           | The visual and accessible wiring around the control        |
| The binding                          | [`FormField`](?path=/docs/ui-forms-form-field--docs) | Value, change, blur and validation state, resolved by name |

## Usage

```tsx
const schema = z.object({
	bio: z.string().max(140, 'Keep it under 140 characters.')
});

<Form form={form} className='grid gap-4'>
	<TextareaField name='bio' label='Short bio' rows={4} description='Optional.' />
</Form>;
```

## Behaviour

- Messages appear once the field has been touched, or as soon as the form is submitted.
- A message clears when the value becomes **valid**, not on the next keystroke.
- `rows` sets the visible height before scrolling. It does **not** cap what can be typed — put the
  limit in the schema, so the user gets a message rather than silently truncated input.

## Accessibility

- The label is a real `<label>` pointing at the textarea, so clicking it focuses the field.
- The description and error share one region, linked by `aria-describedby`.
- If you cap the length, say so in the `description` as well as the schema. A limit someone only
  discovers by hitting it is a poor experience.

## Properties

<ArgTypes />

`name` is the only one you always pass. There is **no `form` prop** — it comes from the surrounding
[`Form`](?path=/docs/ui-forms-form--docs), and rendering this without one throws.
